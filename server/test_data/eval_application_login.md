# Application Authentication and Login Triage

## Overview

This article provides guidance for situations where a user cannot sign in to a company application.

Application login problems can have several possible causes. This article is intended to help identify the issue and determine whether it belongs to an established support category or requires further triage.

## Symptoms

Common symptoms include:

- The application rejects the user's sign-in attempt
- The user cannot authenticate to the application
- The application reports an authentication failure
- The user receives an unexpected login error
- Application access fails even though the application can be opened

## Initial Triage

### 1. Identify the exact application

Confirm the name of the application the user is attempting to access.

### 2. Confirm the account being used

Verify that the user is attempting to authenticate with the intended corporate account.

### 3. Record the exact error

Capture the exact login or authentication message displayed by the application.

Do not rely only on a general description such as "login is not working."

### 4. Determine whether the problem is application-specific

Check whether the user's corporate credentials work normally with other approved services.

If authentication works elsewhere but fails only in one application, additional application-specific investigation may be required.

### 5. Check for an existing known support category

Determine whether the observed behavior clearly matches an established troubleshooting category in the knowledge base.

Do not assign a more specific category without sufficient evidence.

### 6. Escalate when classification remains uncertain

Escalation or additional triage is appropriate when:

- The available symptoms do not clearly match an established support category
- The cause of the login failure cannot be determined
- Further application-specific investigation is required
- Administrative intervention may be necessary

## Important Safety Notes

Do not bypass authentication controls.

Do not disable security controls to work around a login failure.

Do not request or expose user passwords.

Do not attempt unauthorized changes to application permissions or authentication settings.

## Resolution Outcome

The expected outcome is identification of the correct support path for the application login problem.

When the issue does not clearly match a known troubleshooting domain, the case should remain available for further triage rather than being assigned an unsupported resolution.

## Escalation

Escalation is recommended when the available information is insufficient to determine a safe and supported troubleshooting path.
