# Access Permissions Troubleshooting

## Overview

This article provides troubleshooting guidance for users who cannot access a company resource because the required permissions have not been granted or are not being recognized.

Use this guidance when the user can authenticate but access to a specific resource is denied.

## Symptoms

Common symptoms include:

- Permission denied messages
- Access denied messages
- A specific resource cannot be opened
- The user can sign in but cannot access a required system
- Other authorized users can access the resource
- Additional permissions are required for an existing business resource

## Troubleshooting Steps

### 1. Identify the affected resource

Confirm the exact application, folder, service, system, or other company resource that the user cannot access.

### 2. Confirm the user account

Verify that the user is signed in with the intended corporate account.

### 3. Confirm the failure is permission-specific

Determine whether the user can access other company resources normally.

If authentication succeeds but one particular resource is denied, investigate the resource permissions.

### 4. Confirm the expected access

Verify that the user's role and responsibilities require access to the affected resource.

Do not grant access solely because the user reports that it is needed.

### 5. Retry access

Sign out of the affected session and sign back in with the correct corporate account.

Retry the same resource.

### 6. Follow the approved access-request process

If the user does not have the required permission and legitimate business access is required, follow the organization's approved access-request process.

Include the resource and business justification required by the organization.

### 7. Escalate administrative permission issues

Escalate when:

- The user should already have access but is denied
- Administrative changes are required
- Resource ownership approval is required
- The required permission cannot be determined
- The issue persists after account and resource verification

## Important Safety Notes

Do not bypass access controls.

Do not grant elevated privileges as a troubleshooting shortcut.

Do not modify permissions without appropriate authorization.

## Resolution Outcome

The expected outcome is either successful access using existing permissions or completion of the approved process for granting the required access.

## Escalation

Escalation is recommended when administrative permission changes or resource-owner approval is required.
