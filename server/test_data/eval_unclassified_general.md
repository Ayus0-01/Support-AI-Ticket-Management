# General and Ambiguous Support Request Troubleshooting

## Symptoms

Use this guide when a ticket does not contain enough information
to map the issue reliably to a documented technical category.

## Clarify the Problem

Ask the requester to describe what they were trying to do, what
they expected to happen, and what happened instead.

Request the exact error message when one is displayed.

## Identify the Affected Service

Ask which application, device, network service, account, or other
corporate resource is affected.

Determine whether the issue affects only the requester or multiple
users.

## Record Relevant Context

Capture when the problem started, whether it happens consistently,
and what troubleshooting the requester has already attempted.

Do not assume a technical category from a vague statement alone.

## Check Existing Documentation

Search the approved knowledge base using the clarified problem
description.

Use a documented troubleshooting procedure only when the retrieved
documentation clearly matches the issue.

## Escalation

Escalate when the requester cannot provide enough information to
identify the affected service or when the knowledge base contains
no procedure that clearly addresses the reported problem.

Record the information that is missing so the support team can
continue diagnosis.
